# 排序查找与哈希在生信中的应用

> 更新：2026-10-26；状态：可用；验证范围：2026-10-26核对原始与官方资料；本页Python微型计算已执行；人工数据不代表专业软件或真实研究性能。

排序、二分查找和哈希分别回答“怎样排好”“怎样在有序数据中定位”“怎样按精确键访问”。本页用变异位置和重叠k-mer说明它们的输入条件、速度来源和容易丢失的信息。先读[算法输入输出复杂度与数据结构](https://github.com/SpiralKernel/bioinfo-wiki/wiki/%E7%AE%97%E6%B3%95%E8%BE%93%E5%85%A5%E8%BE%93%E5%87%BA%E5%A4%8D%E6%9D%82%E5%BA%A6%E4%B8%8E%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84)；读完应能区分坐标范围查询和ID精确匹配。

## 为什么排序后可以少查很多次

在升序数组里查第一个不小于目标t的位置，每次比较中点：中点小于t，就排除左半部分及中点；否则保留左半部分。始终维护半开搜索范围[lo,hi)，直到lo=hi。每轮候选范围约减半，所以查询为O(log n)。数组未排序时，推理就不成立。

Python的`bisect_left(a,t)`返回最左插入位置，`bisect_right(a,t)`返回最右插入位置。目标不存在时也返回合法位置，不返回“未找到”。若要判断成员资格，需额外检查索引没有越界且值相等。其约定见[Python bisect官方文档](https://docs.python.org/3/library/bisect.html)。

闭区间[L,R]内记录可用`a[bisect_left(a,L):bisect_right(a,R)]`。BED半开区间[L,R)则右边也用left。排序成本通常为O(n log n)，数组中间插入仍需搬移O(n)元素，不能因为“二分定位”就把插入称为O(log n)。

## 一个带重复值的手算

数组`[1,3,3,8]`、目标3：中点索引2值3，保留左侧；中点索引1值3，继续左侧；索引0值1，移动lo到1。左插入点为1，右插入点为3，切片[1:3]保留两个3。去重集合会把这两个记录合成一个位置，因此须先问重复值是重复检测还是不同事件。

> 本页例子在项目根目录的Python中运行；标准库例子无需安装包，含NumPy/SciPy的例子先按[R包Python包与可复现环境](https://github.com/SpiralKernel/bioinfo-wiki/wiki/R%E5%8C%85Python%E5%8C%85%E4%B8%8E%E5%8F%AF%E5%A4%8D%E7%8E%B0%E7%8E%AF%E5%A2%83)建立项目环境。Windows命令使用`python`，macOS/Linux可使用`python3`；代码块可复制进该环境的Python交互会话，或保存为项目根目录下的临时脚本再用该环境解释器运行；不要保存到examples目录或任意外部目录后假定项目导入路径仍相同。除特别说明外，只向屏幕输出，不写文件。

```python
from bisect import bisect_left, bisect_right
from collections import Counter
positions = [1, 3, 3, 8]
left, right = bisect_left(positions, 3), bisect_right(positions, 3)
print('bounds', left, right)
print('closed_3_8', positions[left:bisect_right(positions, 8)])
s, k = 'ATATAT', 2
counts = Counter(s[i:i+k] for i in range(len(s)-k+1))
print('overlapping_kmers', sorted(counts.items()))
assert (left, right) == (1, 3)
assert counts == {'AT': 3, 'TA': 2}
```

输出应为`bounds 1 3`、`[3,3,8]`、AT三次和TA两次。k-mer从每个相邻起点截取，故总数L−k+1=5；按不重叠两字符切割只会得到3个AT，任务已经变了。正式应用还需明确N、大小写、反向互补是否规范化及跨记录边界是否允许；不能把两条contig连接后计跨边界k-mer。

## 哈希为什么适合精确键

字典把键经哈希映射到存储位置，通过冲突处理区分落到同处的不同键。平均或常见摊还意义下查找可近似O(1)，最坏情形不能不加条件地保证。键必须保留完整身份：单独POS=100不够区分染色体、参考版本和不同ALT。注释一对多时使用`dict[id] -> list[annotation]`，不能反复赋值覆盖前面的转录本。

哈希不能直接回答“离位置100最近的是谁”；此类顺序或范围问题用排序数组、树或区间索引。k-mer计数虽然概念简单，但全基因组可能包含海量不同键；Python对象开销远高于原始编码，专业工具会压缩编码、分桶或使用近似结构。

## 输入输出与选型

| 场景 | 先选什么 | 必须保留的检查 |
|---|---|---|
| 一次性检查ID是否存在 | 集合/字典 | 大小写、重复与ID版本 |
| 反复坐标范围查询 | 按染色体排序后二分 | 区间约定、相同参考版本 |
| 所有区间重叠 | 扫描线/区间工具 | 区间长度、链方向、一对多 |
| 统计不同序列窗口 | 哈希计数或专用k-mer工具 | k、方向、模糊碱基、内存 |

## 常见异常与自测

“返回位置等于数组长度”是合法插入点，访问该下标会越界；先检查再取值。“chr10排在chr2前”通常是字符串排序规则，不能用一个字符串比较跨染色体做基因组距离。先分染色体，再按数值位置排序，并使用明确的contig顺序表。

**问：把k从2改为3，ATATAT应有多少窗口？** 答：4个，ATA两次、TAT两次。**问：二分查找前，每次都把一百万条记录重新排序好吗？** 答：少量查询也许可接受，但反复查询应重用同一有序数组或索引，并分别记录构建成本和查询成本。教学实现与综合练习见[基础算法可复现练习](https://github.com/SpiralKernel/bioinfo-wiki/wiki/%E5%9F%BA%E7%A1%80%E7%AE%97%E6%B3%95%E5%8F%AF%E5%A4%8D%E7%8E%B0%E7%BB%83%E4%B9%A0)。
