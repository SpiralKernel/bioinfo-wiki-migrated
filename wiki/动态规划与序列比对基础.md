# 动态规划与序列比对基础

> 更新：2026-10-26；状态：可用；验证范围：2026-10-26核对原始与官方资料；本页Python微型计算已执行；人工数据不代表专业软件或真实研究性能。

动态规划把一个大问题拆成会重复出现的小问题，保存每个小问题的最优结果，再按依赖顺序组合。本页用全局序列比对解释“状态、转移、边界、回溯”，读完应能手填小矩阵、复算对齐分数，理解为什么参数改变会得到不同最优比对。

前置是矩阵下标、最大值和循环。全局比对适合需要比较整个序列的任务；只寻找局部相似片段时转到[Smith-Waterman局部比对](https://github.com/SpiralKernel/bioinfo-wiki/wiki/Smith-Waterman%E5%B1%80%E9%83%A8%E6%AF%94%E5%AF%B9)。

## 从指数枚举到二维状态

把两条长度m、n的序列对齐，每一步可匹配两字符，也可让一方对应缺口。直接枚举全部路径会重复计算相同前缀组合。定义F(i,j)为“前i个字符和前j个字符的最优全局分数”，它只依赖三个较小状态：

$$
F(i,j)=\max\{F(i-1,j-1)+s(a_i,b_j),\ F(i-1,j)+g,\ F(i,j-1)+g\}.
$$

s表示两字符匹配/错配分数，g<0为每个缺口字符的线性罚分。第一项消耗两条序列的字符；第二、三项分别只消耗一方字符。F(0,0)=0，F(i,0)=ig，F(0,j)=jg；这些负边界强制把起始端未对齐字符也计为缺口。[Needleman–Wunsch原始研究](https://doi.org/10.1016/0022-2836(70)90057-4)建立了此类全局最优比较思路。

## 用ACGT和AGT手算

设匹配+2、错配−1、缺口−2。第一行是0、−2、−4、−6；第一列依次0、−2、−4、−6、−8。F(1,1)中A对A，三项为2、−4、−4，取2。最终F(4,3)=4，回溯给出`ACGT`对`A-GT`：3次匹配得6分，1个缺口扣2分。

| 状态行/列 | 空 | A | G | T |
|---|---:|---:|---:|---:|
| 空 | 0 | −2 | −4 | −6 |
| A | −2 | 2 | 0 | −2 |
| C | −4 | 0 | 1 | −1 |
| G | −6 | −2 | 2 | 0 |
| T | −8 | −4 | 0 | 4 |

回溯从右下角开始，沿达到该最大值的来源移动到左上角。同分时可能有多个最优比对；代码固定优先级只输出其中一个。只报总分不能判断路径是否正确，还要去掉缺口后恢复原输入，并逐列重新计分。

> 本页例子在项目根目录的Python中运行；标准库例子无需安装包，含NumPy/SciPy的例子先按[R包Python包与可复现环境](https://github.com/SpiralKernel/bioinfo-wiki/wiki/R%E5%8C%85Python%E5%8C%85%E4%B8%8E%E5%8F%AF%E5%A4%8D%E7%8E%B0%E7%8E%AF%E5%A2%83)建立项目环境。Windows命令使用`python`，macOS/Linux可使用`python3`；代码块可复制进该环境的Python交互会话，或保存为项目根目录下的临时脚本再用该环境解释器运行；不要保存到examples目录或任意外部目录后假定项目导入路径仍相同。除特别说明外，只向屏幕输出，不写文件。

```python
from examples.basic_algorithms_demo import global_alignment
score, left, right = global_alignment('ACGT', 'AGT')
print(score, left, right)
rescored = sum(-2 if '-' in (a,b) else (2 if a == b else -1)
               for a,b in zip(left,right))
assert left.replace('-','') == 'ACGT'
assert right.replace('-','') == 'AGT'
assert score == rescored == 4
print('recomputed_score', rescored)
```

输出`4 ACGT A-GT`和重算4。此例调用项目里可阅读的教学函数，依赖NumPy；不会运行生产比对器，也不处理反向互补、质量值、剪接或软剪切。

## 参数与资源成本

线性缺口模型对长度k缺口罚kg。仿射缺口常写为开缺口罚分加(k−1)次延伸罚分，但不同工具可能采用另一约定，需读文档；它需要额外状态，不能只把g改成两个数。较大的缺口代价会鼓励错配，较小的代价会鼓励更多缺口。分数反映人为指定的比较模型，不直接是进化距离或变异后验概率。

填表时间O(mn)，保存完整表和回溯信息需O(mn)内存。只要最优分数可用滚动行降低内存；恢复完整比对则需额外策略。长基因组常依赖种子、带状DP和索引，不能把小矩阵方法直接用于两条全染色体。

## 怎样判断结果是否值得信任

先确认任务需要全局还是局部，再检查方向与序列完整性。全局比对把长序列两端都罚成缺口，可能正是在完成任务，不是程序故障。相反，若只想定位短read在长参考的位置，全局端点罚分会让分数难解释。模糊碱基和蛋白替换矩阵也需单独指定。

**自测：把缺口罚分改成−5，原比对分数是多少？** 答：仍按原路径计为6−5=1，但新最优路径须重新计算，不能只假定路径不变。**自测：两个比对同分是否都正确？** 答：相对于该评分模型都可能最优；生物学上哪条更可信需要额外证据。继续比较[BLAST原理与种子延伸](https://github.com/SpiralKernel/bioinfo-wiki/wiki/BLAST%E5%8E%9F%E7%90%86%E4%B8%8E%E7%A7%8D%E5%AD%90%E5%BB%B6%E4%BC%B8)的速度与灵敏度取舍。
